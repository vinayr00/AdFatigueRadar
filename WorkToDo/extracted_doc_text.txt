1. Product Goal
AdFatigueRadar is a sandboxed real-time observer and budget-protection guard for paid social campaigns. It combines comment-level audience feedback with delivery/economic telemetry to detect audience fatigue early, explain the signal, and protect simulated spend before material economic degradation.
Core loop: DETECT → EXPLAIN → PREDICT/early-warning → ALERT → PROTECT.
P0 does not depend on a machine-learning predictor. Unless the optional predictor ships, the product language is 'early warning', not 'predicts'.
The demo is a simulation. It must report measured results from held-out replay seeds rather than claim universal 24-hour predictive performance.
No real advertising spend or live campaign mutation is used in the hackathon demo.

6. Replay Architecture
The replay is not a pre-baked outcome file. The generator emits an unconstrained potential world; the runtime simulator applies campaign actions.
6.1 Potential-world JSONL
Each 5-minute step contains potential impressions/volume, CPM, CTR, conversion rate, comment intensity/category mix and optional reach/frequency. These are the scripted conditions that would exist without protection.
6.2 Runtime ActionSimulation
ACTIVE: full potential volume.
SOFT_REDUCED: potential volume × actions.soft_budget_multiplier (default 0.80).
PAUSED: zero new spend/volume after effective pause time.
While PAUSED, emit zero-volume telemetry heartbeats every 5 simulated minutes.
CPA is null when there are zero conversions; never represent it as infinity.
Features/economic ratios are calculated from sums over the rolling hour, not averages of noisy per-step ratios.
Below 20 conversions in the rolling hour, economic risk is N/A and cannot confirm a Path A pause.
Assumption: the replay's underlying economics are scripted and actions only scale volume. Therefore protection mechanically reduces exposure. The meaningful outputs are excess cost avoided per conversion forgone, action timing, and false-positive behavior.
7. Time Semantics
Compute step: 5 simulated minutes.
Guard window: rolling 60 simulated minutes.
Telemetry emits every 5 simulated minutes.
Default comment rate: about 2/minute; stress rate: 8/minute; night lull: 0.4/minute.
Persistence is expressed in simulated hours.
Wall-clock latency is measured separately.
All business logic uses an injectable clock; tests never depend on machine time.

9. 'Again' Labeling Rule
FATIGUE only when the language indicates repeated exposure to the advertisement itself.
'Bro this ad again 😂' → FATIGUE.
'Bought again, love it' → not FATIGUE.
'Ordered again, thank you!' → not FATIGUE.
The labeling guide must include both positive and negative 'again' examples.
10. Two-Score Risk Engine
10.1 Audience Risk
audience_risk =  0.30 × harmful_negative_ratio_signal+ 0.25 × sentiment_decay_signal+ 0.20 × fatigue_mockery_signal+ 0.10 × comment_acceleration_signal+ 0.10 × ctr_frequency_signal+ 0.05 × critical_complaint_signal
10.2 Economic Risk
economic_risk =  0.55 × cpa_cpm_signal+ 0.45 × roas_conversion_signal
10.3 Normalization
Every raw component is normalized as clip((x-low)/(high-low), 0, 1) using thresholds_v4. No business-logic code hard-codes the numeric bounds.
ctr_frequency_signal = mean(normalized CTR decay, normalized frequency increase).
cpa_cpm_signal = max(normalized CPA delta, normalized CPM delta).
roas_conversion_signal = max(normalized ROAS drop, normalized conversion-rate drop).
10.4 Worked Example
The authoritative worked example is generated by check_config.py from thresholds_v4, not manually typed. Its expected headline values are approximately audience_risk=0.781 and economic_risk=0.178. The implementation must reproduce the script's arithmetic.
Example raw inputs:n=120, k_eff=56, decay_per_hr=0.14, fatigue_share=0.30,accel_per_hr=0.08, ctr_decay_pct=25, freq_inc_pct=55,critical_rate=0.04Economic raw inputs:cpa_delta_pct=12, cpm_delta_pct=8, roas_drop_pct=9.5,conv_drop_pct=6
11. Gates, Severity and State
Severity and campaign state are separate axes.

Purpose

Current risk/alert level.
Campaign state
ACTIVE / SOFT_REDUCED / PAUSED / BLOCKED
Actual protection mode.
WATCH at audience_risk >= 0.50.
WARNING at audience_risk >= 0.65 for 0.5 simulated hours. Warning is an alert; it does not change state.
SOFT_REDUCED at audience_risk >= 0.75 for 1.0 simulated hour.
PAUSE Path A requires audience_risk >= 0.85 AND economic_risk >= 0.70 AND evidence/confidence/persistence/cooldown gates.

12. Confidence and Evidence
Per-comment confidence is calibrated confidence after temperature scaling or equivalent calibration.
Window confidence is the mean calibrated confidence across classified comments in the rolling 60-minute window.
Path A uses window mean confidence >= 0.85.
Path B uses mean confidence of critical-complaint comments >= 0.85.
Minimum classified comments = 30.
Minimum distinct authors = 10.
Below the minimum evidence, automated high-severity action fails closed.
13. Path A / Path B Pause Rules
Path A — Economic Confirmation
audience_risk >= 0.85.
economic_risk >= 0.70.
At least 20 conversions in the rolling hour.
Harmful Wilson lower bound >= 0.35.
Path A confidence gate satisfied.
Pause persistence = 0.5 simulated hours.
Cooldown clear.
Path B — Critical Complaint Emergency
Critical complaint categories are product_complaint/service_complaint.
Critical complaint confidence >= 0.85.
Critical complaint rate >= 0.20.
At least 10 distinct authors.
Emergency persistence = 0.25 simulated hours.
Minimal anomaly flag is false.
Cooldown clear.
A keyword alone can never create a critical complaint.
14. P0 Anomaly Flag
Path B requires anomaly_flag=false. P0 uses deterministic checks:
top_author_share > 0.30 → anomaly=true.
duplicate_cluster_share > 0.40 → anomaly=true.
Per-author comments are capped at 3 per rolling window before aggregation.
Either anomaly condition blocks Path B.
15. State Machine and Staleness
ACTIVE → SOFT_REDUCED after sustained soft audience risk.
SOFT_REDUCED → ACTIVE only after audience_risk <= 0.60 for recovery persistence.
SOFT_REDUCED → PAUSED through Path A or Path B.
PAUSED → ACTIVE only through explicit unpause; unpause starts a fresh cooldown.
BLOCKED is an operational safety state.
Stale-data checks run only in ACTIVE and SOFT_REDUCED.
Telemetry staleness = no valid telemetry for more than 2 expected 5-minute emissions.
PAUSED campaigns emit zero-volume heartbeats, so a paused campaign does not become stale/BLOCKED.
Fresh telemetry automatically recovers stale-data protection; explicit operator recovery is reserved for explicit/manual blocks or unsafe configuration.
Alert throttling prevents repeated identical alerts while state and reason remain unchanged.

19. Replay Integrity and Seed Discipline
Replay comments are disjoint from training, validation, LLM-prelabeling and held-out human-test data.
Use varied phrasings per category, not repeated templates.
The ~300 human-audited comments remain the held-out test set.
Report LLM-prelabel vs human-audit agreement.
Tune thresholds, weights and scenario parameters only on tuning seeds.
Freeze all parameters before opening reporting seeds.
Reporting seeds are separate and are never used for post-hoc tuning.
Predictor, if built, also trains and tests on different seeds.
20. 24-Hour Target Calibration
Canonical economic degradation begins at hour 52. A 24-hour lead therefore requires a valid warning by hour 28 or earlier.
The tuning suite must explicitly test the hour-28 gate.
With about 120 comments/hour, the audience components must be sufficiently elevated for audience_risk to cross WARNING by hour 28.
The early-fatigue ramp therefore must be clear enough to cross the configured bounds; it must not be presented as subtle if it is not.
If plausible tuning seeds cannot produce a valid warning by hour 28, adjust normalization bounds or scenario timing on tuning seeds before reporting.
Do not claim the 24-hour target until the held-out reporting seeds demonstrate the measured lead-time distribution.
21. Economic Evaluation
Raw spend reduction is not a savings claim. The system reports efficiency-adjusted excess cost.
excess_cost = spend * max(0, 1 - baseline_CPA / current_CPA)excess_cost_avoided = no_action_excess_cost - protected_excess_costconversions_forgone = max(0, no_action_conversions - protected_conversions)tradeoff = excess_cost_avoided / max(1, conversions_forgone)
Protected and no-action runs use identical potential-world curves and seed.
Report action time, spend, conversions, excess cost, excess cost avoided and conversions forgone.
Do not call the simulated result real monetary savings.
22. Predictor / Early-Warning Evidence
P2 logistic regression is optional. P0/P1 may use the normalized acceleration signal as a heuristic evidence field, but it is not called predictive ML.
If P2 ships: use 5-minute observations, multiple seeds, different train/test seeds, differenced series for correlation, and report AUC/precision-recall plus lead-time distribution.
Do not tune and report on the same generated seed.
If P2 does not ship, use 'early warning' terminology throughout the demo and presentation.
23. Baselines and Negative Controls
Baseline A: raw CPA threshold using baseline_a_cpa_multiplier.
Baseline B: smoothed CPA/CPM threshold.
Baseline C: sentiment-only threshold using raw stage-1 negative sentiment.
CPM surge without sentiment change must not pause.
Banter storm with stable economics must not pause.
Banter is excluded from the combined harmful ratio and category-weighted sentiment decay.
The sentiment-only baseline may fire during banter; this is an explicit demonstration of why the combined guard exists.
24. Security and Reliability
Mutating endpoints require an API-key header.
Thresholds are validated server-side against safe bounds.
Threshold changes are audit events with old/new values and config version.
Comment text is safely escaped in React; never inject raw HTML.
Author IDs use HMAC with an environment-provided secret.
Provider/Slack secrets live only in environment variables.
Pause is idempotent.
Pause read-back verifies PAUSED state.
Unpause resets cooldown and requires fresh persistence before re-pause.
Uncertainty, missing evidence and failed read-back fail closed.
25. NLP Replay Performance
Cache replay NLP outputs keyed by comment_id + model_version + preprocessing_version.
Cached replay outputs are allowed for demo speed after validation.
Live inference benchmark bypasses the cache.
Measure sub-minute classification latency early.
If CPU latency is too high, batch or quantize/use a smaller model before dashboard polish.
Pre-cache model weights in a local volume/artifact so first run does not depend on internet.

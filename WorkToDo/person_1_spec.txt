AdFatigueRadar — PERSON 1AI / NLP Execution Specification
Isolated parallel-work package • P0 first • P1/P2 optional
1. Mission and Boundary
Person 1 owns the AI/NLP layer only. The goal is to convert raw replay/live comments into deterministic, calibrated NLP outputs that the backend risk engine can consume without Person 1 modifying risk logic, action logic, replay economics, API routes, or frontend code.
Primary outcome: reliable two-stage comment classification with the frozen NLP output contract.
P0 outcome: general sentiment + custom 8-class taxonomy + confidence + critical-complaint flag + latency benchmark.
P1 outcome: sentiment-only baseline artifact.
P2 outcome: optional predictor work only after P0 is stable.
All replay comments used for evaluation must be newly authored and disjoint from training/test data.

5. Frozen Input and Output Contract
Person 1 consumes CommentEvent records. The canonical input is:
{  "event_id": "comment_0001",  "timestamp": "2026-09-30T12:00:00Z",  "campaign_id": "campaign_01",  "ad_id": "ad_07",  "author_id": "author_184",  "text": "Bro this ad again 😂",  "reactions": 12,  "replies": 3}
Person 1 emits exactly the NLP fields below; backend owns aggregation and risk calculation:
{  "comment_id": "comment_0001",  "sentiment": "negative",  "sentiment_score": 0.91,  "category": "fatigue",  "confidence": 0.94,  "critical_complaint": false}
Do not add action/state/risk fields to this contract.
Do not compute audience_risk or economic_risk inside NLP.
Do not mutate campaign state.
Do not call pause/unpause APIs from NLP.
6. Frozen Taxonomy
The custom taxonomy contains exactly eight categories:
product_complaint
service_complaint
fatigue
mockery
spam
banter_meme
neutral
positive
Category weights are consumed by the risk layer and must NOT be duplicated as decision logic in Person 1's classifier.
Important semantic rule: 'again' means fatigue only when it indicates repeated exposure to the advertisement. Examples:
“Bro this ad again 😂” → fatigue
“Bought again, love it” → positive
“Ordered again, thank you!” → positive
7. Two-Stage NLP Design
7.1 Stage 1 — General Sentiment
Return positive / neutral / negative.
Return a calibrated confidence/score suitable for downstream reporting.
This stage exists independently from the custom taxonomy.
Raw stage-1 negative share is reserved for the sentiment-only baseline and must not replace the weighted harmful-share definition.
7.2 Stage 2 — Custom Ad-Fatigue Taxonomy
Classify each comment into exactly one of the eight taxonomy classes.
Return confidence.
Return critical_complaint only when the complaint criteria are satisfied.
Banter/meme content must not be converted into harmful complaint categories merely because sentiment is negative.
Humorous mockery may be mockery, but banter_meme must remain non-harmful.
8. Critical Complaint Logic
Person 1 owns the NLP classification of complaint categories and the calibrated confidence. The final rate gate is a backend concern.
Eligible categories: product_complaint and service_complaint.
Minimum classifier confidence: 0.85.
Optional safety/critical keywords may assist classification, but keyword presence alone must never create a critical complaint.
Person 1 should expose enough metadata for backend aggregation but must not decide the campaign action.
9. Training and Data Leakage Controls
Create explicit train/test manifests.
Keep test_human_audited separate from training data.
Replay comments must be newly authored and disjoint from both training and test sets.
Do not use replay-generated labels to train the model.
Do not tune thresholds against the held-out reporting replay seeds.
Record model version and preprocessing version with every cached result.
If LLM-assisted pre-labeling is used, human-audit a representative sample and record provenance.
Do not silently overwrite the human-audited labels.
10. Labeling Guide
Create a concise labeling guide before large-scale labeling. It must define:
product complaint vs service complaint
fatigue vs mockery
mockery vs banter_meme
spam vs repeated genuine complaint
neutral vs positive
repeated-ad exposure vs genuine repeated purchase/order
critical complaint criteria
uncertain/ambiguous examples and adjudication rules
11. Model and Preprocessing Requirements
Use HuggingFace Transformers or the project-approved local NLP stack.
Normalize whitespace and obvious formatting noise without destroying semantic cues such as emojis or repetition.
Preserve enough context to distinguish 'this ad again' from 'bought again'.
Keep preprocessing deterministic and versioned.
Support CPU execution for the hackathon environment.
Benchmark a practical model before selecting a larger model.
If CPU inference is too slow, benchmark batching, quantization, or a smaller model rather than changing the project contract.
Model weights should be cached locally and should not be downloaded on every replay.
12. Caching
Implement replay-safe NLP caching keyed by:
comment_id + model_version + preprocessing_version
A cache hit may accelerate replay but must not be used to claim live latency.
Live latency benchmark must bypass the cache.
Cache format must be deterministic and safely invalidated when model/preprocessing versions change.
13. Latency Benchmark
Measure end-to-end NLP classification latency on the target machine.
Measure both single-comment and batched inference.
Report p50, p95, and worst observed latency.
P0 target: sub-minute classification latency.
Clearly separate cold-start model loading from steady-state inference.
Do not hide slow inference by using replay cache.

18. P1 — Sentiment-Only Baseline
Create a baseline using only Stage-1 raw negative sentiment.
It must be clearly labeled as a baseline, not the production combined guard.
Its purpose is to demonstrate that sentiment-only detection can react to banter/meme conditions that the combined weighted guard should suppress.
Do not alter the production risk engine to accommodate the baseline.
19. P2 — Optional Predictor
P2 is optional and must not block P0.
Use five-minute observations if implemented.
Use multiple seeds and separate train/test seeds.
Prefer differenced time series for correlation analysis.
Report AUC, precision-recall, and lead-time distribution.
If no trained predictor is shipped, expose prediction_score as null or explicitly label any acceleration heuristic as heuristic—not predictive ML.
Do not claim the project predicts future CPA degradation unless held-out evidence supports that claim.
